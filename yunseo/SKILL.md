## 1. 표 1 — 기본 데이터

채권 하나 + 날짜 하루 = 1행. `bond_info_raw`(채권 정보)와 `bond_market`(시세)을 채권번호(isin)로 합쳐서 만들어요.

| 만들 컬럼 | 어디서 가져오나 | 주의할 점 |
| --- | --- | --- |
| date | 시세 파일의 날짜 | 채권정보 파일의 날짜(수집일)를 쓰면 안 돼요. 그건 그냥 "이 정보를 언제 받아왔는지"일 뿐 시세 기준일이 아니에요 |
| isin | 두 파일 공통 | 두 파일을 합칠 때 기준이 되는 값 |
| bond_name | 시세 파일 쪽 이름 | 채권정보 파일의 이름이랑 표기가 다를 수 있어서 시세 파일 걸 우선 씀 |
| issuer | 채권정보 파일 | 시세 파일에는 없어서 꼭 합쳐야 나옴 |
| bond_type | 채권정보 파일의 세부 종류 | 아래 1-1 참고 (생각보다 종류가 많아요) |
| credit_rating | 채권정보 파일의 신용등급 | 아래 1-2 참고 (평가기관이 4곳이에요) |
| issue_date / maturity_date | 채권정보 파일 | 발행일·만기일 |
| remaining_maturity | 만기일 - 오늘 날짜 | 일수로 계산하고, 필요하면 연 단위로도 표시 |
| coupon_rate | 채권정보 파일 | 표면금리(%) |
| interest_payment_cycle | 채권정보 파일 | "3개월"처럼 글자로 되어 있어서, 나중에 계산할 때 "1년에 몇 번 이자 주는지" 숫자로 바꿔야 함 |
| close_price / ytm / volume / trading_value | 시세 파일 | 그대로 가져오면 됨 |

### 1-1. bond_type — "회사채/국채" 두 개가 아니라 실제로는 10종류 → 6종으로 확정

> **정정**: 이전 버전에서 원본 종류 이름을 잘못 옮겨적었어요(터미널 한글 표시가 깨져서 다른 이름으로 착각). 아래는 파일로 직접 다시 확인해서 정정한 정확한 값이에요.

실제로 채권정보 파일 안에는 이런 종류들이 있어요 (많은 순서대로): **일반회사채(9,528) · 금융채(9,036) · 유동화SPC채(3,281) · 특수채(2,729) · MBS(1,864) · 지방채(1,348) · 지방공사채(607) · 국채(479) · 유사집합투자기구채(199) · SLBS(17)**.

원하시는 건 "회사채 / 국채" 두 종류로 보이는데, 실제 데이터는 훨씬 세분화돼 있어서 아래 6종으로 묶기로 확정했어요. (이 6종 분류는 국내 채권시장에서 흔히 쓰는 "국채/지방채/특수채/금융채/회사채/유동화증권" 구분과도 맞아떨어져요.)

| bond_type (확정) | 포함되는 원본 `scrsItmsKcdNm` | 매핑 후 건수 |
| --- | --- | --- |
| 국채 | 국채 | 479 |
| 지방채 | 지방채, 지방공사채 | 1,955 |
| 특수채 | 특수채 | 2,729 |
| 금융채 | 금융채 | 9,036 |
| 회사채 | 일반회사채 | 9,528 |
| 유동화증권 | 유동화SPC채, MBS, SLBS, 유사집합투자기구채 | 5,361 |

### 1-2. credit_rating — 신용평가사가 4곳, 절반 정도는 등급 자체가 없음 → 우선순위 확정

신용등급을 매기는 곳이 KIS·KBP·NICE·FN 4곳이라 컬럼도 4개예요. 각각 채워진 비율은 56~58% 정도고, 나머지는 원래부터 등급이 없는 채권들(국채·지방채처럼 국가/지자체가 발행하는 것들)이라 비어 있는 게 정상이에요.

다행인 점: 두 평가사 값이 둘 다 있는 경우(16,469건)를 비교해봤더니 **등급이 서로 다른 경우가 한 건도 없었어요**. 그래서 순서 자체가 결과를 크게 바꾸진 않고, **채움률이 높은 순서대로 `KIS(57.6%) → FN(57.0%) → KBP(56.6%) → NICE(56.6%)`** 순으로 확정했어요. 앞 순서 값이 있으면 그걸 쓰고, 없으면 다음 순서로 넘어가는 방식이에요.

### 1-3. 실제 예시로 따라가기

채권 하나를 실제로 뽑아서 표1의 한 행이 만들어지는 과정을 그대로 보여드릴게요.

**1단계: 같은 채권번호(isin)를 두 원본 파일에서 각각 찾는다**

`bond_market.csv`(시세 파일)에서:
```
isin_code = KR310506AFB6
bond_name = 기업은행(단)2511할304A-17
close_price = 9961.6
close_yield = 3.431
volume = 44250000
trading_value = 44074851
date = 2026-08-07
```

`bond_info_raw.csv`(채권정보 파일)에서 **같은 isin**을 찾으면:
```
isinCd = KR310506AFB6
isinCdNm = 중소기업은행(단) 2511할304A-17   ← bond_name이랑 표기가 살짝 다름
bondIsurNm = 중소기업은행                    ← 발행사, 시세파일엔 없던 정보
scrsItmsKcdNm = 금융채
kisScrsItmsKcdNm = AAA
bondIssuDt = 20251117
bondExprDt = 20260917
bondSrfcInrt = 2.78
intPayCyclCtt = 12개월
```

**2단계: 두 개를 이 채권번호 기준으로 옆으로 이어붙인다** (isin이 "같은 채권"이라는 걸 확인하는 열쇠 역할)

**3단계: 원본에 없어서 직접 계산해야 하는 값 채우기**
- `remaining_maturity` = 만기일(2026-09-17) − 기준일(2026-08-07) = **41일**

**4단계: 완성된 표1의 한 행**

| date | isin | bond_name | issuer | credit_rating | maturity_date | remaining_maturity | close_price | ytm |
|---|---|---|---|---|---|---|---|---|
| 2026-08-07 | KR310506AFB6 | 기업은행(단)2511할304A-17 | 중소기업은행 | AAA | 2026-09-17 | 41일 | 9961.6 | 3.431 |

→ 이렇게 채권 359개 각각에 대해 이 과정을 반복하면 표1이 완성돼요.

## 2. 표 2 — 시장 흐름 데이터

이건 채권과 상관없이 "그날 시장 전체 상황"을 담는 표예요. `market_rates_daily.csv`와 `cpi_monthly.csv`를 합쳐서 만들어요.

| 만들 컬럼 | 어디서 / 어떻게 | 주의할 점 |
| --- | --- | --- |
| base_rate | 이미 있는 컬럼 그대로 | 바로 사용 가능 |
| cpi_yoy | 물가지수로 "1년 전 대비 몇 % 올랐는지" 계산 | 아래 2-1 참고 |
| yield_spread_10y_3y | 이미 계산돼 있는 컬럼(이름만 다름) | 이름만 맞추면 끝 |
| credit_spread / policy_spread | 이미 있는 컬럼 그대로 | 바로 사용 가능 |
| short_rate_change | 오늘 3년물 금리 − N일 전 3년물 금리 | 아래 2-2 참고 |
| long_rate_change | 오늘 10년물 금리 − N일 전 10년물 금리 | 아래 2-2 참고 |

### 2-1. cpi_yoy — 물가지수를 상승률로 바꿀 때 생기는 문제

- 물가지수는 2015년 1월부터 있는데, "1년 전 대비"를 계산하려면 1년치 과거 데이터가 필요해서 **2015년 첫 1년은 상승률을 계산할 수 없어요** (그냥 빈 값으로 둬야 함).
- 물가지수는 한 달에 한 번만 나오는데 시세는 매일 있어요. "이번 달 값을 그 달 1일부터 쭉 채워 넣는" 방식으로 하면 간단하지만, 사실 통계청이 그 달 물가를 발표하는 건 보통 다음 달 초라서, 발표 전 날짜에도 이미 그 값을 아는 것처럼 계산되는 셈이에요. 완벽하게 하려면 "발표일 이후부터 적용"해야 하는데, 지금 단계에서는 단순하게 가고 이 한계만 기록해두는 정도로 타협해도 될 것 같아요.

### 2-2. short_rate_change / long_rate_change — N = 20영업일로 확정

요청하신 표에 "N일 전"이라고만 되어 있고 며칠 전인지가 안 정해져 있었는데, **20영업일(약 1개월 전)**로 확정했어요. 1주일(5영업일)보다 하루 이틀 출렁임에 덜 흔들리고, "금리추세"라는 표현에 더 가까워서 이걸로 골랐어요.

### 2-3. 실제 예시로 따라가기

같은 2026-08-07 기준으로 표2 한 행이 만들어지는 과정이에요.

**1단계: `market_rates_daily.csv`에서 2026-08-07 행을 그대로 가져온다**
```
base_rate = 2.75
treasury_3y = 3.746   treasury_10y = 4.208
credit_spread = 0.702   policy_spread = 0.996
yield_spread(10y-3y) = 0.462   ← 이게 요청하신 yield_spread_10y_3y
```
이 6개는 계산 없이 그대로 복사하면 끝이에요.

**2단계: cpi_yoy는 물가지수 두 달치를 가져와서 직접 계산해야 함**
```
2026-07월 CPI = 119.77
2025-07월 CPI(1년 전) = 116.52
cpi_yoy = (119.77 − 116.52) / 116.52 × 100 = 2.79%
```
→ CPI는 월별이라 8월 시세에는 "가장 최근 발표된" 2026-07월 값(2.79%)을 그대로 채워 넣는 거예요.

**3단계: short_rate_change / long_rate_change — 확정된 N=20영업일로 계산**

20영업일 전(2026-07-09) 금리와 비교하면:

| 구분 | 오늘(8/7) | 20영업일 전(7/9) | 변화 |
|---|---|---|---|
| 3년물 (short) | 3.746 | 3.778 | 3.746 − 3.778 = **−0.032** |
| 10년물 (long) | 4.208 | 4.25 | 4.208 − 4.25 = **−0.042** |

(참고로 5영업일 전과 비교하면 −0.012 정도로 훨씬 작게 나와요 — N을 20영업일로 정한 이유가 바로 이 차이 때문이에요.)

**4단계: 완성된 표2의 한 행**

| date | base_rate | cpi_yoy | yield_spread_10y_3y | credit_spread | policy_spread | short_rate_change | long_rate_change |
|---|---|---|---|---|---|---|---|
| 2026-08-07 | 2.75 | 2.79 | 0.462 | 0.702 | 0.996 | −0.032 | −0.042 |

이 표2는 채권과 무관하게 **날짜당 딱 한 줄**이라, 359개 채권 전부가 이 한 줄을 공유하게 돼요 (나중에 표3 만들 때 date로 조인).

## 3. 표 3 — 파생 데이터

표 1과 표 2를 합친 다음 계산으로 만드는 값들이에요. 계산 자체보다 **"어떤 채권에 대해 계산해도 되는지"가 더 중요한 문제**예요.

| 만들 컬럼 | 계산 방법 | 필요한 것 |
| --- | --- | --- |
| macaulay_duration | 앞으로 받을 이자·원금을 현재가치로 환산해서 가중평균 만기를 구함 | 이자 지급 스케줄을 직접 만들어야 함 |
| modified_duration | macaulay_duration ÷ (1 + 수익률/이자지급횟수) | 위 결과 + interest_payment_cycle을 숫자로 바꾼 값 |
| short_price_sensitivity / long_price_sensitivity | -modified_duration × (표2의 금리 변화) | 표 2와 합쳐야 함 |
| real_yield | ytm − cpi_yoy | 표 2와 합쳐야 함 |
| relative_yield_spread | ytm − 비교할 국고채 금리 | 아래 3-2 참고 |
| expected_maturity_profit | 만기에 받을 돈(원금+남은 이자) − 지금 매수가격 | 이자 지급 스케줄 필요 (duration 계산과 같은 걸 재사용) |
| expected_maturity_return | expected_maturity_profit ÷ 매수가격 | |

### 3-1. 콜/풋옵션 채권, 변동금리 채권은 이 계산이 잘 안 맞아요

- **중도상환 옵션(콜/풋)이 있는 채권이 전체의 약 32%(9,250건)** 나 돼요. 이런 채권은 "서류상 만기일"과 "실제로 상환될 가능성이 높은 날"이 다를 수 있어서, 서류상 만기일 기준으로 duration이나 만기수익을 계산하면 실제와 안 맞을 수 있어요. → 1차로는 **옵션 없는 채권만 계산 대상으로 하고**, 옵션 있는 채권은 별도 표시만 해두는 걸 추천해요.
- **표면금리에 변동금리 요소가 있는 채권도 있어요** (`irtChngDcdNm`에 "변동"이 들어간 경우 1,107건, 전체의 3.8%). 이런 채권은 미래에 이자를 얼마 받을지 지금 확정할 수 없어서, duration이나 만기 예상 수익 계산 자체가 불가능해요. → **고정금리 채권만** 계산하는 게 안전해요 (고정금리만 있는 채권이 27,981건으로 전체의 96.2%라 충분히 넓은 범위예요).
- interest_payment_cycle 값이 아예 비어 있는 채권도 429건 있어요. 이자를 정기적으로 안 주는 할인채로 보이는데, 이런 건 이자 스케줄이 아니라 "만기에 한 번에 상환" 방식으로 따로 계산해야 해요.

### 3-2. relative_yield_spread — 비교할 국고채가 3년·5년·10년물뿐

채권의 남은 만기가 이 세 구간(3/5/10년)에 딱 안 맞으면(예: 남은 만기 6개월, 또는 20년) 어떤 국고채 금리와 비교할지 애매해요. 특히 만기가 1년도 안 남은 채권이 꽤 많아서, 이런 걸 3년물이랑 비교하면 비교 자체의 의미가 흐려질 수 있어요. 1차로는 "제일 가까운 만기물을 그냥 쓴다"로 단순화하고, 이게 완벽하진 않다는 걸 기록해두면 될 것 같아요.

### 3-3. 신용등급은 "오늘 기준"이라, 나중에 과거 날짜와 합칠 때 조심해야 해요

채권정보 파일이 하루짜리 스냅샷이다 보니, 앞으로 시세 데이터가 여러 날짜로 쌓이기 시작하면 "과거 그 날짜에도 지금이랑 똑같은 신용등급이었다"고 가정하는 셈이 돼요. 발행일·만기일·표면금리는 시간이 지나도 안 바뀌니 상관없지만, **신용등급은 실제로 바뀔 수 있는 값**이라서 나중에 시계열 데이터가 쌓이면 이 부분을 다시 점검해야 해요. (지금은 데이터가 하루치뿐이라 당장은 문제가 안 보여요.)

## 6. 실제로 만들어보면서 새로 확인된 점 (2026-08-11)

`yunseo/scripts/`에 코드를 짜고 `yunseo/output/`에 CSV 3개(+ 중간 산출물 2개)를 실제로 만들어봤어요. `SKILL.md`의 예시 채권(KR310506AFB6)·예시 날짜(2026-08-07)로 손계산 대조까지 마쳤고, 그 과정에서 추가로 알게 된 것들이에요.

- **이자 지급일은 실제 날짜가 아니라 근사치예요**: `bond_info_raw.csv`에 실제 다음 이표일(`nxtmCopnDt`) 컬럼이 있지만, 이번 1차 구현에서는 쓰지 않고 "오늘부터 만기까지를 지급주기(m)로 균등 분할"하는 방식으로 근사했어요. duration류 계산이 실제 이표일 기준보다는 조금 부정확할 수 있다는 뜻이에요.
- **`expected_maturity_return`은 연 환산이 아니에요**: 스펙 그대로 "예상 이익 ÷ 매수가격"이라 만기까지 남은 기간과 무관하게 그 기간 전체의 누적 수익률이에요. 그래서 만기가 아주 많이 남은 채권(예: 잔존 40년 이상 지방채)은 200%가 넘는 값도 정상적으로 나와요 — 틀린 게 아니라 "연 몇 %"가 아니라 "만기까지 총 몇 %"라는 뜻이라 해석할 때 주의가 필요해요.
- **일부 지방채가 액면 대비 크게 낮은 가격에 거래돼요** (예: 액면 10,000원인데 close_price 5,000~8,000원대). 장기·저표면금리 채권이 현재 금리보다 낮은 이자를 주니까 시장에서 할인되어 거래되는, 정상적인 현상이에요. 다만 `expected_maturity_profit/return` 계산이 "액면 10,000원 상환"을 그대로 가정하고 있어서, 혹시 이 채권들이 원금이 점점 상환되는 구조(예: 분할상환)라면 이 가정이 안 맞을 수 있어요 — 지금 가진 원본 컬럼만으로는 분할상환 여부를 확인할 수 없어서 1차 구현에서는 반영하지 않았어요.
- **`bond_type` 원본 카테고리 이름을 한 번 잘못 옮겨적었었어요**: 터미널에서 한글이 깨져 보여서 "국민주택채권/통안증권/은행채" 같은 다른 이름으로 착각했었는데, 파일을 직접 다시 확인해서 정정했어요(1-1 참고). 실제 이름은 **일반회사채/금융채/유동화SPC채/특수채/MBS/지방채/지방공사채/국채/유사집합투자기구채/SLBS**예요.
