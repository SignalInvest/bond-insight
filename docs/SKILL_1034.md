# BOND BRIDGE 리디자인 — 구현 계획 (2026-08-13)

> 목업 이미지("BOND BRIDGE" 대시보드)를 기준으로 현재 화면(`BOND LEDGER`, `docs/SKILL.md` 결과물)을
> 다시 짜는 작업. 이 문서는 **다음 세션들에서 Step 단위로 그대로 실행할 계획서**이며, 아직 구현은
> 시작하지 않은 상태(계획만 확정)입니다.

## 진행 방식 (중요)

- **Step은 순서대로 하나씩만 진행한다.** 한 Step이 끝나면 결과(변경 파일, 실행 확인 내용)를
  보고하고, 다음 Step으로 넘어가도 되는지 확인받은 뒤에 이어간다. 여러 Step을 한 번에 몰아서
  구현하지 않는다.
- 각 Step은 "이 Step만 봐도 뭘 하는지 알 수 있게" 아래에 구체적으로 적어둠 — 세션이 끊겨도 이
  문서만 보고 이어갈 수 있어야 함.

5. **Bond Screener는 이번 단계에서 DB 연동하지 않는다.** Mock 데이터(하드코딩된 TS 배열)로

## 3. 확정이 필요한 설계 결정 (내가 제안한 규칙 — Step 시작 전 확인)

### 3-1. "시장상황" 3분류 규칙 (정상/하락/상승 금리 구조)
이미지엔 "정상 금리 구조"의 조건만 나와 있음(`Yield Spread(10Y−3Y) > 0`). 하락/상승 조건은
요구사항에 규칙 자체가 없어서 다음을 제안함 — **Step 2 시작 전에 확인받을 것**:

- `spread = treasury_10y − treasury_3y`
- `spread > 0` → **정상 금리 구조** ("장기금리가 단기금리보다 높은 구조")
- `spread ≤ 0` (역전)이면서 기준금리가 최근(전일 대비) **인상 추세** → **상승 금리 구조**
  (긴축 국면, 장단기 역전)
- `spread ≤ 0`이면서 기준금리가 최근 **인하 추세(또는 보합)** → **하락 금리 구조** (완화 국면)

한 줄 설명 문구는 실제 계산된 `spread`, 대소 관계를 넣어 동적으로 생성
(예: `"장단기 금리차 {spread:+.2f}%p, 장기금리가 단기금리보다 {높은/낮은} 구조입니다."`).

### 3-2. 날짜 선택(기준일) 동작
- 상단바 날짜 입력은 실제로 선택 가능한 `<input type="date">`.
- 현재 백엔드 데이터는 `2026-08-07` 하루치뿐(`MarketOverview.tsx`의
  `DASHBOARD_REFERENCE_DATE`) → 이 날짜를 기본값으로 하고, 다른 날짜를 고르면 Bond Market·
  Bond Overview 두 섹션은 "선택한 날짜에는 데이터가 없습니다" 형태의 빈 상태를 보여준다
  (임의 값 채우지 않음, `yunseo/AGENT.md` 원칙과 동일).
- Bond Screener는 이번 단계엔 mock 데이터라 날짜와 무관하게 항상 동일한 목록을 보여준다
  (DB 연동 시점에 재검토).

### 3-3. Bond Screener 필터 버튼 = 3개의 독립 토글 그룹 + 전체 리셋
- **그룹 A (채권유형)**: 국채 / 회사채 — 상호 배타, 아무것도 선택 안 하면 전체 유형 표시
- **그룹 B (전략)**: 안정성 중심 / 수익률 중심 — 상호 배타
- **그룹 C (만기)**: 단기채 / 장기채 — 상호 배타
- **전체** 버튼: A/B/C 모든 선택을 초기화(리셋)하는 버튼이지 그룹 멤버가 아님.
- 드롭다운(채권종류/신용등급/잔존만기)과 검색창은 버튼 그룹과 **AND 조건**으로 함께 적용.

### 3-4. Mock 데이터에 포함할 필드 (Bond Overview 4지표 계산이 가능하도록)
`GET /api/bonds` 응답 형태(`backend/app/services/bond_service.py`)를 참고해서, mock 데이터
타입에 아래를 전부 포함 — 나중에 실제 API 응답으로 교체할 때 필드명을 맞추기 위함:

```ts
interface MockBond {
  isin: string;
  bondName: string;      // 채권명
  issuer: string;        // 발행사
  bondType: "국채" | "회사채"; // 유형
  creditRating: string;  // 신용등급
  remainingMaturityYears: number; // 잔존만기
  ytm: number;            // YTM(수익률), %
  couponRate: number | null; // 표면금리, %
  price: number;          // 현재가격, 원 (액면 10,000원 기준)
  issueDate: string | null;
  maturityDate: string;
  tradingValue: number | null; // 오늘 거래량(유동성) 계산용
  creditSpread: number | null; // 신용 스프레드(bp 환산 전, 소수)
  modifiedDuration: number | null; // Duration
  tags: ("안정성 중심" | "수익률 중심" | "단기채" | "장기채" | "거래 활발" | "수익률 높음")[];
}
```

### 3-5. AI Analysis 패널과 mock ISIN의 불일치
`/api/ai/explain`은 Supabase에 실제로 존재하는 ISIN이어야 200을 반환함. Mock 데이터의 ISIN이
Supabase에 없는 채권이면 404가 남 — 이 경우 패널에 에러를 그대로 보여주지 않고
**"이 채권은 아직 AI 분석 데이터가 없어요"** 같은 안내로 처리한다(3단계 fallback 원칙과 동일,
`docs/SKILL.md` 1-7 참고). 가능하면 mock 데이터의 ISIN 몇 개는 실제 Supabase에 있는 값
(`docs/SKILL.md`에 언급된 국고채 ISIN 등)으로 채워서 정상 동작도 한 번은 확인할 것.

## 6. 구현 완료 기록 (2026-08-13)

Step 1~6 전부 구현하고 브라우저(Playwright)로 검증까지 마침. 실제 구현하면서 계획과 달라진 점만 남김:

- **3-1 시장상황 규칙**: 제안한 규칙 그대로 채택. 2026-08-07 실데이터가 우연히 목업 이미지 값과
  거의 일치해서(`정상 금리 구조`, `+0.46%p` 등) 상승/하락 분기는 실데이터로 검증 못 함 — 로직만
  확인됨.
- **CPI 표시 형식**: 이미지는 지수값(`119.77`)이지만, 기존 `/api/market`의 `cpi_yoy`(전년比 %)를
  그대로 재사용하기로 한 결정(0-4) 그대로 감. 실제 값은 `2.79%`로 표시됨.
